# SCSS и сборка стилей

Основные требования: [AGENTS.md](../../AGENTS.md). Весь собственный SCSS и результат сборки находятся в дочерней теме.

## Структура

```text
assets/scss/
  main.scss                  # точка входа, @use модулей
  settings/_tokens.scss      # общие значения и семантические CSS-переменные
  components/_buttons.scss   # интеграция кнопок с токеном Savoy
  components/_hero.scss      # баннеры и viewport слайдера
assets/css/main.min.css      # production-результат, хранится в Git
package.json
package-lock.json           # зафиксированное дерево зависимостей
```

Используется Dart Sass через npm. Gulp для компиляции одного входного файла не нужен. `node_modules` и внешние source maps не коммитятся. Сборщик нужен только на машине разработки, WordPress на сервере получает готовый CSS.

## Команды

- `npm ci` — установить зависимости по lockfile; Node.js >=20.19.0.
- `npm run build` — минифицированный CSS без source map; ошибки SCSS завершают сборку с ненулевым кодом, CSS с текстом ошибки не генерируется.
- `npm run dev` / `npm run watch` — наблюдать за SCSS и автоматически пересобирать минифицированный CSS с внешней source map. Используется `--poll`, чтобы не зависеть от доступности macOS FSEvents в окружении разработки.
- После работы watch останови процесс и выполни `npm run build`, чтобы production-файл не содержал ссылку на локальную карту.

Обновляй браузер после изменения стилей: live reload не подключён. `functions.php` загружает результат после исходного child `style.css` с `filemtime` для сброса кеша. Корневой `style.css` остаётся файлом метаданных; новые стили пиши в SCSS.

## Добавление компонента

1. Создай `components/_component-name.scss` и подключи его один раз через `@use` в `main.scss`.
2. Повторно используй семантические CSS-переменные из `settings/_tokens.scss`. Переменные Sass вводи там, где нужны вычисления/условия на этапе компиляции, например для media query; не дублируй те же значения без необходимости.
3. Для существующих компонентов Savoy используй его токены/хуки, когда они подходят. Не копируй CSS всей родительской темы и не применяй глобальный `!important`.
4. Собери и проверь браузер на desktop/mobile, hover/focus, состояния и AJAX. Храни обновлённый `main.min.css` вместе с исходником.

## Начальные токены

- `--jd-radius-sm: 6px`, `--jd-radius-md: 12px`.
- `--jd-radius-button` и `--jd-radius-hero` — семантические ссылки на размеры.
- `--nm--border-radius-button` переопределяется на `body` через проектный токен. Это меняет стандартные кнопки, submit и CTA баннеров, использующие родной токен Savoy, не превращая стрелки и точки слайдера в кнопки другого вида.
- Скругление slider viewport сохраняет мобильную пагинацию снаружи картинки; целиком компонент не обрезается новым `overflow: hidden`.

Не добавляй новую палитру, шрифты и размеры ради количества переменных: вводи токены по фактической задаче.

## Первичная проверка — 2026-11-24

- `npm ci --offline` из заполненного кеша, production-сборка, PHP syntax и `git diff --check` прошли.
- Watch проверен реальным изменением токена в partial-файле и последующим восстановлением; оба изменения автоматически попали в CSS. Процесс watch после проверки остановлен.
- На `http://juvelyrinisdarbas.local/` проверены viewport 1920×847 и 390×844. CSS загружается с версией `filemtime`, фактический радиус hero/viewport — 12px, CTA — 6px; горизонтального переполнения нет, мобильная пагинация не обрезается.
- Для скруглений использован предоставленный владельцем референс. Проверка относится к форме углов, а не к полному совпадению контента, типографики и композиции.
- В мобильной конфигурации WPBakery первого баннера остаётся отдельная демофотография `banner-750x500-1.jpg`, а Savoy выводит CTA текстом в альтернативной мобильной раскладке. Это существующие настройки контента, этой задачей не менялись.
- Переключение слайдов кликами при проверке не подтверждено: активной оставалась первая точка. Это не считается пройденным функциональным тестом слайдера и требует отдельной диагностики при работе над его поведением.
