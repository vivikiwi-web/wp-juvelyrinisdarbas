## Исходные данные

- В двух похожих именах фотографий отмечена необходимость проверки возможных дубликатов. Это отдельные кандидаты до решения владельца.

Пустые характеристики остаются пустыми. Все модели без подтверждённого наличия. Только два черновика имеют условную цену: `JD-0001` — 390 EUR, `JD-0033` — 590 EUR. Изначально это были примеры оформления. По последнему поручению отметка примера и запрет публикации отменены; сами значения цен не менялись.

## Команды

Установленная CF7 требует PHP >=8.3 для полного bootstrap. Используй PHP Local 8.5 через wrapper, а не PHP 8.2 из старого примера аудита:

```sh
bash scripts/wp-local.sh jd catalog import
bash scripts/wp-local.sh jd catalog import --only=JD-0001,JD-0033,JD-0041,JD-0052,JD-0054 --apply --report=/private/tmp/jd-catalog-import.json
bash scripts/wp-local.sh --user=1 eval-file tests/catalog-inquiry.php
```

Без `--apply` команда только проверяет план. `--apply` по умолчанию ограничен пятью товарами. Более крупная партия требует отдельного согласования владельца и явного `--allow-full`; импорт всё равно создаёт только черновики. Публикацию не добавляй автоматически.

`jd catalog setup` создаёт отдельную форму CF7, если её ещё нет; существующие формы сохраняются. ID новой формы хранится в опции `jd_inquiry_form_id`.

UUID товара и изображения обеспечивают повторный запуск без дублей. При совпадающем входном JSON уже созданный товар пропускается, ручные правки не перезаписываются. Если входные данные изменились, команда выдаёт конфликт и требует отдельного рассмотрения обновления. Полная синхронизация изменённых товаров пока намеренно не реализована.

## Администрирование

Характеристики редактируются в штатной вкладке WooCommerce `Savybės`: можно добавлять произвольные или глобальные атрибуты и включать их видимость. Наличие задаётся через `Atsargos`; сохранение больше не перезаписывает stock status. В `Katalogas ir užklausa` находятся разрешение пожеланий и редактор полей попапа для конкретного товара.

`Pavyzdinė kaina` и блокировка публикации удалены. Цена остаётся штатной ценой WC. Поле `price_is_example` в исходном JSON — историческое, импорт его не использует и не создаёт соответствующее метаполе.

Кнопка `Užsakyti individualiai` рядом с запросом открывает модальный попап. Для пары колец есть два диаметра. `Tęsti užklausą` добавляет пожелания в панель Savoy, где клиент заполняет контакты и отправляет заказ-запрос через CF7. Пожелания не меняют факты и цену исходного изделия.

Для переноса старых метаполей: `jd catalog migrate-attributes` — dry-run, `jd catalog migrate-attributes --apply` — запись после резервной копии. Существующие стандартные атрибуты при совпадении названий имеют приоритет; значения остаются в резервной копии. Цены, stock status, публикация и импортные идентификаторы не меняются.

## Запрос и проверки

Контакты CF7: имя, телефон, email обязательны, комментарий необязателен. Список до 10 моделей сохраняется в `sessionStorage` той же вкладки без контактов. Сервер проверяет модели, доступ к черновикам, применимость полей, числовые значения и сочетание материала/цвета. Названия и SKU берутся заново из WooCommerce.

Заказ `wc-jd-inquiry` создаётся на сервере перед отправкой. Идемпотентный ключ и блокировка предотвращают повторное создание; при ошибке письма запись остаётся для повторной отправки. Оплата и списание заблокированы для помеченных запросов. В тестах создаётся только собственная временная запись, которая затем удаляется; прямой тест сервиса не отправляет почту.

## Условия активности полей — 2026-11-24

В каждой строке редактора добавлена `Aktyvavimo sąlyga`:

1. `Visada aktyvus` — поле доступно всегда; либо выберите другой список этого товара.
2. `Palyginimas`: `Yra` (равно) / `Nėra` (не равно).
3. `Reikšmė` — вариант из выбранного списка, включая пустой пункт `Aptarti su juvelyru`.

Пример для цвета золота: `Pageidaujama medžiaga → Nėra → Sidabras`. При серебре значение цвета очищается, поле блокируется. Правило задаётся так же для любых новых полей и не зависит от их названий. Источником может быть только список; условие не выполнено, если источник выключен или сам неактивен. Возможны цепочки; циклы, ссылки на удалённые поля и варианты не сохраняются. После удаления источника нужно исправить зависимое правило или выбрать `Visada aktyvus`.

Старая связь `material`/`gold_color` преобразуется в видимое правило при чтении прежних конфигураций, без массовой записи БД. Явно сохранённое `Visada aktyvus` имеет приоритет. Прежние отдельные JS-обработчики и серверная проверка по именам полей заменены универсальной проверкой схемы. На сервере значения неактивных полей отклоняются, а не попадают в заказ.
