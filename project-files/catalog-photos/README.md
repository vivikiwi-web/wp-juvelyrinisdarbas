# Исходные фотографии Juvelyrinis darbas

Собрано 2026-11-24: **64 фотографии** с двух указанных страниц, общий размер файлов — **53 444 017 байт** (около 53,4 МБ). Это фотографии этих галерей, а не вся медиатека старого сайта.

## Где смотреть

- [index.html](index.html) — локальная галерея со всеми фото, номерами и ID. Открой файл в браузере; сервер и WordPress не требуются. Нажатие на фото открывает исходный файл.
- [manifest.json](manifest.json) — реестр: страница, точная подпись `Nr. …`, номер, старый ID вложения, исходные имя/URL, локальное имя, разрешение, размер и SHA-256.
- `originals/vestuviniai-ziedai/` — 32 фотографии, обручальные кольца.
- `originals/suzadetuviu-ziedai/` — 9 фотографий, помолвочные кольца.
- `originals/ziedai/` — 10 фотографий, остальные кольца.
- `originals/juvelyriniai-dirbiniai/` — 13 фотографий, другие ювелирные изделия.

Это ручная раскладка владельца. Галерея сгруппирована по этим локальным папкам. В JSON поле `local_group` обозначает локальную группу, `local_file` — текущий путь; `local_folder_counts` содержит количество фотографий по папкам. Поля `source_section` и `section_counts` по-прежнему описывают два исходных раздела сайта (по 32 фото), а не новые локальные группы. Номера, ID, исходные названия файлов и контрольные суммы не изменены. Названия уже скачанных файлов сохранены, даже если их часть `ziedai`/`kiti-gaminiai` отличается от имени новой папки.

Источники:

- https://www.juvelyrinisdarbas.lt/vestuviniu-ir-suzadietuviu-ziedu-gamyba/
- https://www.juvelyrinisdarbas.lt/kitu-gaminiu-gamyba/

Для выбора полного разрешения использована публичная WordPress Media API по ID изображений, найденным в галереях. Для 24 фотографий полный файл отличается от уменьшенного файла, открываемого самой галереей. Ширина сохранённых файлов — от 1024 до 3648 px. Проверены декодирование всех файлов, размеры по исходным метаданным и контрольные суммы; ошибок скачивания нет.

## Имена и номера

Пример: `juvelyrinis-darbas-ziedai-nr-293-src-3896.jpg`.

- `nr-293` — номер из подписи старого сайта, а не новая придуманная нумерация.
- `src-3896` — постоянный ID исходного вложения WordPress; это ID фотографии, не доказанный ID товара.
- Подпись `Nr. 100 Klasika` сохранена полностью в реестре и как `nr-100-klasika` в имени. Суффикс `22M` также сохранён.
- В разделе колец повторяются номера 49, 52, 56 и 122 (по два снимка). Все фото сохранены отдельно; автоматически считать их одним изделием или разными товарами нельзя.
- Совпадающих по SHA-256 файлов среди 64 фото нет.

В `proposed_title_lt` подготовлены только нейтральные предложения: `Žiedai Nr. 293`, `Juvelyrinis gaminys Nr. 241`. Они ещё не утверждены владельцем и не импортированы в WooCommerce. Названия не утверждают материал, пробу, характеристики камней, цену или наличие.

## Исходники и последующая обработка

Файлы в `originals/` сохранены байт-в-байт: фон, штампы даты и EXIF пока не менялись. Два файла Samsung (ID 3808 и 3788) имеют расширение `.jpg`, но содержат JPEG/MPO. Они сохранены как опубликованы, без перекодирования; формат и число кадров отражены в реестре.

Для будущей обработки сохраняй копии в отдельной папке `edited/` с тем же основным именем, например `juvelyrinis-darbas-ziedai-nr-293-src-3896-edited.png`. Не перезаписывай исходники. Если редактор не принимает MPO, экспорт первого кадра готовится отдельно и не заменяет оригинал.

Предлагаемое направление обработки: спокойный светло-серый фон, чистая подача и аккуратные свет/тени. Убирать можно штамп даты фотоаппарата и посторонний фон. Сохранять геометрию изделия, число и расположение камней, узор, гравировку и клейма; не дорисовывать технические свойства или элементы украшения. Сначала обработать небольшую пробную партию и согласовать результат.

Обработка изображений, создание товаров, изменение БД и публикация в эту задачу не входят.

## Повторный сбор

Из корня дочерней темы:

```sh
python3 scripts/collect-catalog-photos.py
```

Нужны Python 3, Pillow и доступ к старому сайту. Скрипт сначала находит перемещённые исходники по SHA-256 и сохраняет существующую раскладку папок; затем проверяет файлы по реестру и не скачивает их повторно. Файл с неизвестной или изменённой контрольной суммой не перезаписывается. Новые фото, которых ещё нет в реестре, первоначально попадают в папку исходного раздела. Скрипт не обращается к локальной БД и не меняет старый сайт.

После следующего перемещения или переименования файлов обнови только локальные пути и галерею без доступа к сети:

```sh
python3 scripts/collect-catalog-photos.py --sync-local
```

Команда сверяет содержимое файлов по SHA-256, а не только по имени. Если исходник отсутствует, изменён или найдено несколько неоднозначных копий, обновление останавливается до записи реестра. Несопоставленные дополнительные фотографии перечисляются в `unmapped_local_files`, но не превращаются в изделия автоматически. Категории WooCommerce эта команда не создаёт.

Оригинальные фотографии исключены из Git через `.gitignore`: они остаются локально в этой папке. Для передачи всей подборки нужно передавать папку с файлами, а не только commit. Реестр, инструкция, скрипт и HTML-каталог могут храниться в Git.
