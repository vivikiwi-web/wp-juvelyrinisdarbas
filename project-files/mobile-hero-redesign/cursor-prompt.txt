ЕДИНСТВЕННОЕ ДОПОЛНЕНИЕ PHP — ПОЛЕ НАД ЗАГОЛОВКОМ
CSS не может создать новое редактируемое поле WPBakery. Добавь его как расширение существующего nm_banner через API WPBakery и хук WordPress из child theme; сами плагины и Savoy не редактировать.

Поле:
- shortcode: nm_banner;
- param_name: jd_eyebrow;
- тип WPBakery: textfield;
- название в редакторе: «Viršutinė antraštė»;
- подсказка: «Trumpas tekstas virš pavadinimo mobiliajame baneryje. Neprivaloma.»;
- необязательное, по умолчанию пустое;
- это простая строка, не HTML и не автоматически вычисляемая категория.

Точки расширения фактически проверены:
- vc_add_param() существует в js_composer/include/helpers/helpers_api.php;
- vc_after_init вызывается установленным WPBakery;
- core do_shortcode_tag передаёт ($output, $tag, $attr, $m).
Выбери подходящий этап регистрации после объявления nm_banner, проверь результат в редакторе. Можно использовать vc_after_init + vc_add_param('nm_banner', ...).

Установленный nm_banner не имеет отдельного хука перед title и не читает jd_eyebrow. Одной регистрации поля недостаточно. В небольшом child-модуле (например inc/hero-banner.php) обработай готовый вывод nm_banner через do_shortcode_tag: только для $tag === 'nm_banner' и непустого скалярного jd_eyebrow. Аккуратно вставь РОВНО ОДИН <p class="jd-banner-eyebrow">…</p> внутри .nm-banner-text-inner перед существующим title. Значение очистить как простую строку и вывести через esc_html. Если ожидаемая структура не найдена — вернуть исходный вывод. Не пересобирай весь баннер или страницу и не вызывай do_shortcode рекурсивно. Не переопределяй nm_shortcode_banner() и не заменяй регистрацию оригинального шорткода.
Пустое значение не должно создавать элемент, отступ или менять баннер. Элемент скрыт на desktop и отображается только в целевом мобильном hero. Название, значение и видимость не должны быть зашиты через CSS content или зависеть от image_id.
Подключи модуль из functions.php. Никаких иных собственных frontend-компонентов/JS в этой задаче.
