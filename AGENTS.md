# Juvelyrinis darbas — инструкции проекта

Это основной источник требований и ограничений для агентов. Сначала читай этот файл, затем документ соответствующего процесса из `docs/workflows/`. Правила Cursor ссылаются сюда. Прямое актуальное поручение владельца имеет приоритет; предложения из документации не становятся согласованными решениями сами по себе.

## Общение и продукт

- Общайся с владельцем по-русски. Весь пользовательский сайт, формы, ошибки, уведомления и письма клиентам — только на литовском языке.
- Бренд: „Juvelyrinis darbas“. Мультиязычность и переключатель языка не нужны.
- Это ювелирный каталог с запросами на готовые изделия и индивидуальное изготовление. Стандартные покупка, онлайн-оплата и checkout не планируются.
- WooCommerce хранит каталог, изображения, SKU, характеристики и состояние наличия. Contact Form 7 отправляет запросы. Страницы редактируются в WPBakery.

## Границы изменений

- Собственный PHP, JS, CSS, шаблоны и интеграции размещай только в `savoy-child`.
- Родительскую Savoy, WordPress и сторонние плагины разрешено читать, но запрещено редактировать.
- Сначала используй хуки Savoy/WooCommerce; переопределяй шаблоны только при обоснованной необходимости.
- Собственные стили пиши в `assets/scss/`: общие токены в `settings/_tokens.scss`, компоненты в отдельных partial-файлах, подключение через `@use` в `main.scss`. Сборка `npm run build` создаёт `assets/css/main.min.css`; результат хранится в Git и подключается темой. Не редактируй скомпилированный CSS вручную. Процесс: `docs/workflows/styles.md`.
- Сохраняй выбранную компоновку Savoy: белый фон, свободное пространство, спокойная типографика, крупный hero, четыре колонки каталога на desktop, адаптивность, акцент на фото и сдержанные золотистые детали.
- Не создавай логотип и изображения hero без отдельной задачи. Концепты из другого чата не считаются доступными изображениями.
- Не меняй старый действующий сайт и не выполняй деплой без отдельного поручения.
- Страницы, товары, формы и настройки находятся в БД. Git не откатывает БД. Перед разрешёнными массовыми изменениями подготовь отдельное восстановление вне Git и отчёт о затрагиваемых данных.
- Не делай слепой SQL search-and-replace сериализованных данных. Для записи используй подходящие API WordPress/WooCommerce.
- Не запускай отправку реальных писем при проверке без соответствующего поручения; используй проверенный локальный перехватчик писем.

## Git

1. Перед работой проверь корень репозитория, ветку, `git status` и существующие изменения.
2. Новая самостоятельная задача — отдельная ветка; продолжение той же задачи — её существующая ветка. Не реализуй изменения в `main`.
3. Не удаляй и не перезаписывай изменения владельца. Не выполняй merge или force push без отдельного поручения.
4. Не коммить пароли, ключи, `wp-config.php`, персональные данные, дампы и резервные копии. Не коммить коммерческую Savoy и сторонние плагины.
5. Не переинициализируй существующий Git и не меняй remote без проверки. При отсутствии Git честно сообщи, что ветку и diff проверить невозможно.
6. На 2026-11-24 до инициализации локального Git не было; при первоначальном аудите удалённый репозиторий был пуст. Корень репозитория — эта папка `savoy-child`, начальная ветка — `chore/project-foundation`, origin — https://github.com/vivikiwi-web/wp-juvelyrinisdarbas.git. Текущую ветку всегда проверяй командой, а не по этому историческому описанию. Не переинициализируй этот репозиторий.

## Каталог и данные

- Подтверждены категории: `Vestuviniai žiedai`, `Sužadėtuvių žiedai`, `Auskarai`, `Pakabukai`.
- `Žiedai` и `Grandinėlės` обсуждались; `Apyrankės` возможна. Не создавай их автоматически до подтверждения.
- Услуги представлены отдельно от товаров: индивидуальное изготовление, ремонт ювелирных изделий, изменение размера колец, ремонт оправ очков (включая титан), холодная микроплазменная сварка. Окончательные литовские названия и тексты ещё не согласованы.
- Материал (золото/серебро) и цвет золота (жёлтое/белое/красное) — разные параметры.
- Не превращай все пожелания клиента в вариации WooCommerce. Неизвестные проба, вес, состав, характеристики камней, сертификаты, наличие и цена остаются незаполненными до подтверждения.
- Не выдумывай отзывы, гарантии, опыт и сертификаты.

## Панель запроса

- Используй дизайн существующей правой панели Savoy, адаптируя её через хуки и необходимые переопределения в child theme. Не создавай другой дизайн панели без поручения. Кнопка предполагается с текстом `Pateikti užklausą`.
- Панель показывает фото, название, SKU, разрешённый сценарий и параметры изделия; контактные поля и отправка — CF7.
- Наличие задаёт администратор. Если разрешены оба сценария, клиент выбирает готовое изделие или изготовление по заказу.
- Сервер заново проверяет ID изделия, публикацию, доступность сценария и параметры. Не доверяй названию, цене, SKU и скрытым полям браузера.
- Владелец уточнил: форма запроса размещается в нижней части панели, запрос сохраняется как заказ WooCommerce. Прежнее предложение отдельного типа записей вместо заказов отменено.
- Заказ-запрос не оплачивается, не резервирует и не уменьшает остатки. Рекомендуется отдельный статус `Užklausa`; его техническое имя и жизненный цикл ещё не утверждены.
- Bioresus — пример связи панели, CF7 и заказа, но там создаётся заказ `processing`. Не переноси этот статус, создание заказа из браузерного события успеха и глобальное разрешение покупки без переработки.
- Цена может потребоваться не для всех изделий; окончательная политика не решена. Не заменяй неизвестную цену нулём, не скрывай все цены глобально и не показывай общий итог как полную стоимость при наличии изделий без цены.
- Форму CF7 не помещай внутрь AJAX-фрагмента списка без обоснованной защиты введённых данных и жизненного цикла формы. Проверяй влияние Catalog Mode на включение самой панели Savoy.
- Catalog Mode Savoy скрывает элементы через CSS; он не заменяет серверный запрет покупки и проверку стандартных, AJAX и Store API путей.
- Согласованные требования и открытые решения разделены в `docs/decisions.md`. До реализации разреши только вопросы, от которых зависит конкретная задача; не спрашивай повторно уже известное.

## Проверка и отчёт

- Документация: проверяй ссылки, согласованность требований и frontmatter `.mdc`; не запускай сборки сайта ради правок текста.
- PHP/JS/CSS: проверяй синтаксис изменённого кода и поведение, затронутое задачей. Не добавляй формальные тесты, повторяющие реализацию.
- Для пользовательского интерфейса проверяй desktop/mobile, клавиатуру, состояния загрузки и ошибок, взаимодействие с AJAX Savoy. Сравнивай с предоставленными референсами; не заявляй о совпадении с отсутствующим макетом.
- Для запросов проверяй подмену данных, устаревшую доступность, ошибки отправки, повторную отправку, создание ровно одного заказа-запроса, отсутствие оплаты, резервирования и изменений остатков.
- Для импорта обязательны dry-run, тестовая партия, повторный запуск без дублей и отчёт ошибок. Полный импорт — после согласования.
- В отчёте указывай выполненное, файлы, фактические проверки, изменения БД (или их отсутствие) и ограничения. Не называй проверку успешной, если её не выполнял.
